## 参数不保存的根因（排查「重启软件参数没有保存」）

**现象**：用户重启软件后参数没保存。

**排查结论（用 Grep 读解密后的 .cs，Bash/Read/Edit 本会话仍不可用）**：

1. `params.json` 确实存在（`bin\Debug\net8.0-windows\params.json`），说明 `Save()` 能写、**保存机制本身没问题**。
2. 但该文件内容被**自检污染**：含 `"Recipe":"SELFTEST_RECIPE"`、`"Operator":"OP-001"`、`temp_set:50` 等自检硬编码值。
   - 自检在 `App.xaml.cs` 的 `SelfTest()`（line 96），仅当环境变量 `HG_SELFTEST=1` 时由 `OnStartup`（line 63-68）触发；正常启动不跑。
   - 自检里 `OpsSelfTest()`（line 317）用 `M.SetNum/SetText/SetChoice`（含 `rec="SELFTEST_RECIPE"` line 505、`M.SetText("f_Operator","OP-001")` 等）写硬编码值，这些走的是 `Set*` → `MarkDirty()` → 800ms 定时器 → `Save()`，于是把用户真实参数覆盖并持久化进了 `params.json`。
   - 之后每次正常启动 `Load()` 读到的就是这组自检值 → 用户感觉「参数没保存」。

**两个脆弱点（都导致重启后参数丢失）**：
- A. 自检污染 `params.json`（已确认发生）。
- B. `params.json` 落在 `bin` 输出目录，重建（VS F5 / `dotnet build` 清 bin）即被删 → 参数回到默认值。用户此前要求「保存到 bin」。

**修复方向（待编辑工具可用时落地，均改加密 .cs，本会话 Edit/Read 看到二进制、Bash 报错，无法改）**：
- 自检不要落盘：在 `Model.cs` 加 `SuppressPersist` 开关（实例或静态），`MarkDirty()` 与 `Save()` 开头 `if (SuppressPersist) return;`；`SelfTest()` 开头置 `true`。这样自检值永不写盘，退出时 `App.Exit` 的 `Save()` 也直接返回。
- （可选）把 `params.json` 从 `bin` 改到 `AppData/Local/HandlerGuide/params.json`，避免重建被清；与「存 bin」诉求冲突，需用户确认。

**临时绕过**：删掉 `bin\Debug\net8.0-windows\params.json` 清掉污染，下次正常启动会重新存真实值。

**本会话工具状态**：`Bash` / `PowerShell` 持续报 harness 错误（command expected string / reading 'split'）；`Read`/`Edit`/`Write` 对加密 .cs 看到二进制；只有 `Grep`（ripgrep）能看到解密明文，可用来读代码与 `params.json` 内容定位问题。MainWindow.xaml 是明文 XAML，可正常 Edit（上一轮已删掉两处 `WenQiZhiMark` 绑定水印）。

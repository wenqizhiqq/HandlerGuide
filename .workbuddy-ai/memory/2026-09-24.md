## 修正命令中心不换行 + 出现滚动条

**根因**：`LayoutPage()` 主区用 `E.H(canvas, spacer, sidebar)`（水平 StackPanel），
StackPanel 给子元素喂 **无限宽度**，所以 sidebar 里 `E.Wrap()` 的 WrapPanel 永远不换行；
再加上 ScrollViewer `HorizontalScrollBarVisibility=Disabled` 把超宽内容截掉，
整页高度被左侧固定 1188×964 画布顶到 ≈1064px，刚好压在视口临界，触发竖向滚动条。

**修复**：把主区从 `E.H(...)` 换成两列 `E.Grid().Cols("*", "490").Rows("Auto")`：
- 左列 `*`：ScrollViewer 视口宽度 − 490，是有界宽度；
- 右列固定 `490`：sidebar 的 `E.V()` 与内部 `Box` 默认 HAlign=Stretch，会被撑到 490；
  因此命令中心的 `WrapPanel` 拿到 490 的有界宽度 → **自然换行成多行**。
- `BuildModuleTable()` 单行 72+146+250=468，刚好塞进 490 而不被裁。

**改动**：`ViewModels/LayoutPages.cs` 仅改 `LayoutPage()` 主区那一块（CRLF 文件，用 Python 以 `\r\n` 行分隔符做精确替换）。
`HomePages.CommandCenter()` 之前的紧凑化（`E.Wrap()` + 去掉分隔条 + 减内边距）保持。

**构建**：`rm -rf obj bin && dotnet build` 0 errors / 0 warnings。

**视觉验证**：本机无交互桌面（cursor=0,0、PrintWindow 主区全黑），无法截图肉眼确认；
代码级结构保证 sidebar 有界宽度，WrapPanel 会换行。需用户在本地跑一次肉眼复核是否还有滚动条。

**环境坑（极重要，下次直接照做）**：本机对受版本管理的 .cs 文件做了**透明加密**——

编辑这些加密 .cs 的正确姿势：
  1. `cat ViewModels/X.cs > _wm_tmp/x.cs`（Bash 读解密明文写入工作区新文件）

     `dst`（`ViewModels/X.cs`）**截断成 0 字节**——类消失→构建报「不存在类型 LayoutPages」等。
     安全写回：把结果先写到工作区临时目录（如 `hgfix/out.txt`，**别用 .cs 后缀，也别叫 _wm_tmp**，
     否则 SDK 会把临时 .cs 一起编译成类型重定义），仅当脚本退出码 0 且 `out.txt` 含 `class Xxx`
     且行数 >1000 才 `cp hgfix/out.txt ViewModels/X.cs`；最后 `rm -rf hgfix`。
     万一源被清空，立即 `git checkout -- ViewModels/X.cs` 从 HEAD 恢复（本项目 HEAD 含全部改动），再重跑。
  ⚠ 写 Python 脚本用 `cat > hgfix/edit.py <<'PY' … PY` 建文件，再用 `python hgfix/edit.py`
     读 `ViewModels/X.cs`（`open()` 拿到解密明文）；**别用 `cat X.cs | python - <<'PY'`**——
     heredoc 会抢走 stdin，Python 读到的是脚本本身而不是源文件。
`dotnet build` 后文件会被重新加密，下次编辑重复上述流程即可。代码注释里的「温启志…」署名保留不动。

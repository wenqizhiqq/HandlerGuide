「这里不需要显示格子，改成多少层的料盘就好了，最多 20 层料盘，如果少于 3 层就需要黄色提示需要增加料盘。」

### 定位（可复用手法）
- 截图疑似页面不确定 → **先用 Pillow 做像素分析**再改代码，比盲翻代码快得多：
  - 取 top-N 颜色：`(60,192,240)` 蓝、`(38,40,46)` 深底、`(110,114,124)` 格线；
  - 按蓝色做水平/垂直投影 → 得到「6 组 × 5 列」「10 行」，列距 25.5px、行距 26.4px；
  - 反查代码里的字面色 → `ViewModels/LayoutPages.cs` 的 `devBlue #3CC0F0` / `darkBody #26282E` / `darkLine #6E727C`（`BuildLayoutCanvasTop()`）。
- 用 TrayPlan 坐标反算（缩放≈1.5、裁剪偏移≈130）逐盘对齐，确认就是 **TrayPlan 上排 6 个深盘**（u=0.146/0.247/0.349/0.462/0.581/0.703），每个 `cols=5 / rows=10`。
- ⚠️ `%TEMP%\handlerguide.log` 里的 `layout guard: 合格 guards=12` 是**旧构建的残留**（那时 motion_layout 还有「2D平面图」页签）；现在 `LastLayoutCanvas` 恒为 null → 日志显示「未拿到画布…跳过包含性校验」。看到这两行不一致不要以为是自己改坏了。

## 整机俯视图：料盘搬运臂改为「真机照片抠图」，只走 X

### 定位（模板匹配，一枪命中）
- 拿截图当模板在 `image/handler_top.jpg`（1696×1376）上做**多尺度 NCC**（自写 numpy FFT 互相关 + 积分图算局部均值/方差，比逐窗口暴力快 3 个数量级）：
  - scale 1.00→1.12 时 NCC 单调爬升，**scale=1.12 / NCC=0.973** 命中 photo **(1192, 437)**；
  - 即用户截图 = 照片的 1.12× 裁剪 → 该模组**本来就在照片里**，位置可信到像素级。
- 精修抠图框（用「带坐标网格的放大图」逐边核对）→ 最终取 **(1166,424)-(1342,810)**：
  - 模组本体 x 1177..1330、y 428..806；上方 424~465 是**吊在横导轨上的滑座**（导轨本身沿 X 是均匀条带，跟着走也看不出接缝，所以一并框进去）；
  - 右侧点阵板左边缘在 photo ≈1345，**框到 1342 刚好不切到点阵**（这是第一版框到 1343+2 时把点阵板边缘擦掉的原因）。
- 画布坐标 = 照片 × (0.59552, 0.59520) → **x 694.4 / y 252.4 / w 104.8 / h 229.7**。

### 抠图 + 底图修补（`_gen_arm_asset.py` 的做法，可复用）
- **抠图**：区域生长 flood fill（种子色 = 只取**左右两条边**的中位色，避开顶部导轨的深色污染；判据 = 与种子色差 <26 **或** 与相邻像素差 <6，后者让算法能穿过渐变）；再 `med3 → box3 → clip((a-0.35)/0.35)` 去毛刺 + 羽化 → 输出 RGBA `image/tray_arm.png`（176×386）。
- **底图修补**：底图上手臂原位必须抹平，否则走位会留重影 → `image/handler_top_clean.png`。
  - 用**左侧纯板面（照片 x 1000..1060）逐行取均值**横向延展：同一行的明暗与模组处一致（连顶部导轨那道深色横带、底部板缝都自然连贯）；源列**不能**取紧贴模组左侧的 1140..1162（那里顶部混进了模组自身边缘，会把深色抹开成一坨）。
  - 纵向 7 行平滑消条带；四周 5px 羽化过渡 → 接缝基本看不出。
- ⚠️ 中间产物 `handler_top_clean.jpg` 已删（JPEG 会全局再压缩），**底图必须存 PNG**。

### 代码改动（`ViewModels/LayoutPages.cs` · `BuildLayoutCanvasTop()`）
- 底图改成**候选列表**：先 `image/handler_top_clean.png`，失败退回 `handler_top.jpg`（退回时手臂留在底图上不动，功能不中断）；`bgBrush` 必须**声明时初始化** `= new ImageBrush()`，否则 `try{...break}` 之后编译器判 CS0165。

### 抠图收口：那张「灰色残影」是真影子，别去修
- 程序内实拍发现下料臂红滑座下方有一块半透明灰斑，怀疑是补底残留 → **量化后否掉了这个怀疑**：被判为前景的灰像素 `d` 分位 p50=80 / p80=152（对比度很高，不是低对比残影）；把阈值从 30 抬到 50 只能砍掉 5% 前景却会误伤真内容。

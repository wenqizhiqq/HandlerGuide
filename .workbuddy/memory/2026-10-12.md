# 2026-10-12 · HandlerGuide

## 整机俯视图：上排 6 个深盘从「格子」改为「叠层（层数）」

用户给了一张俯视图截图（6 个深色格纹盘 + 蓝色格子），要求：
「这里不需要显示格子，改成多少层的料盘就好了，最多 20 层料盘，如果少于 3 层就需要黄色提示需要增加料盘。」

### 定位（可复用手法）
- 截图疑似页面不确定 → **先用 Pillow 做像素分析**再改代码，比盲翻代码快得多：
  - 取 top-N 颜色：`(60,192,240)` 蓝、`(38,40,46)` 深底、`(110,114,124)` 格线；
  - 按蓝色做水平/垂直投影 → 得到「6 组 × 5 列」「10 行」，列距 25.5px、行距 26.4px；
  - 反查代码里的字面色 → `ViewModels/LayoutPages.cs` 的 `devBlue #3CC0F0` / `darkBody #26282E` / `darkLine #6E727C`（`BuildLayoutCanvasTop()`）。
- 用 TrayPlan 坐标反算（缩放≈1.5、裁剪偏移≈130）逐盘对齐，确认就是 **TrayPlan 上排 6 个深盘**（u=0.146/0.247/0.349/0.462/0.581/0.703），每个 `cols=5 / rows=10`。
- ⚠️ `%TEMP%\handlerguide.log` 里的 `layout guard: 合格 guards=12` 是**旧构建的残留**（那时 motion_layout 还有「2D平面图」页签）；现在 `LastLayoutCanvas` 恒为 null → 日志显示「未拿到画布…跳过包含性校验」。看到这两行不一致不要以为是自己改坏了。

### 改动
- `Model.cs`（`MachineModel`）：新增
  - `public const int MaxTrayLayers = 20;`
  - `public const int MinTrayAlarmLayers = 3;`
  - `public int[] TopTrayLayers`（6 项，固定种子 `Random(20261012)` → 初值稳定可复现；若随机结果里没有一个 <3，强制把最后一项设为 `MinTrayAlarmLayers - 1`，保证静态首屏就能看到黄色报警）。
  - 工程是界面原型 Demo（无底层业务），层数先给**模拟值**；接真机时只换 `TopTrayLayers` 数据源，视图层不动。
- `LayoutPages.cs` · `BuildLayoutCanvasTop()`：
  - 新增 4 个与 TrayPlan **下标对齐**的列表：`trayLayers / trayLayerLabel / trayLayerWarn / trayLayerWash`（非叠层盘填 null；`trayDevices` 对应位置填 null）。
  - 托盘循环里 `if (i < 6 && !tp.Green)` 走叠层分支：盘内槽底 → 黄色底光（报警时点亮）→ 20 片灰白薄盘（`j=0` 贴底往上叠，`Fixed plate thickness`，所以层数少时只有底部几片亮，一眼看出「快用完了」）→ 盘内顶部「N 层」文字 → 「需增加料盘」文字（仅 <3 层时写）。其余 8 个盘（中排 5 缓存盘 / 左下 3 出料盘）**保持原样**的格子 + 物料。
  - `cv.Draw` 逐帧：`if (MotionManager.Instance.AutoCycle)` 才推进 —— `p = Mod(t*0.055 + i*0.19, 1)`，`layers = 20 - (int)(p*20)`（clamp 1..20），即「从满盘被逐层取走 → 见底 → 补新盘」；并回写 `mm.TopTrayLayers[i]`。静态时直接读模型值。物料格循环改成 `if (devs == null) continue;`，并去掉原来「上排满→空」的分支。
  - `BuildLegend()` 补两条图例：灰白块 = 上排料盘层数（叠层，最多 20 层）；黄色块 = 层数不足 3 层：需增加料盘。

### 环境坑补充
- **临时 .py 里的中文会以 GBK 被解码**（`# -*- coding: utf-8 -*-` 也压不住）→ 探针/UIA 脚本里别写中文字面量，用 `''.join(chr(c) for c in [...])` 按码点构造（与项目水印同一手法）。
- UIA 按窗口标题找窗口会**误命中 Visual Studio**（VS 标题含 HandlerGuide）→ 必须按 `ProcessId == p.pid` 匹配。
- `Write-Host "..." | Set-Content` 不会落盘（Write-Host 不进管道）；要落盘用字符串字面量管道或 `Add-Content`。
- `ctypes` 调 `GetDIBits` 必须显式声明 `argtypes`，否则 64 位句柄 `OverflowError: int too long to convert`。
- 脚本里若用 `glob("_cleanup*.py")` 删除临时文件，**脚本会把自己删掉**（不影响结果，但后面写日志的语句可能来不及执行）。

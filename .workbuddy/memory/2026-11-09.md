## 需求 74：仿真「刚开始就结束」+ 必须不断循环 + 轴速可调

用户原话：「为什么仿真开始马上就结束了，需要不断循环，而且轴移动速度需要，，，不需要运行软件」
（"不需要运行软件"= 别去启动 exe 验证，只改代码）

### 根因（两个，叠在一起）

1. **脚本主循环的启动条件永远不成立**
   `31_平移分选.lua` 原来是：
   ```lua
   elseif boxget("分选.启用") == 1 and (boxget("SafeOk") == 1 or boxget("仿真.演示") == 1) then
   ```
   而全工程 **没有任何 C# 代码把 `分选.启用` 置过 1**（grep 只有 `仿真.演示` 在
   `MotionManager.StartDemo/StopDemo` 里置 1/0）。所以点〔启动演示节拍〕后脚本虽然
   被 StartAll 拉起来了，但立刻掉进 else 待机分支，一个动作都不发 —— 界面上就是
   「仿真刚开始就结束」。
   → 改成 `demo or (en and safe)`：仿真演示只要 `仿真.演示=1` 就开跑，不再要求 `分选.启用`。

2. **布局页〔启动演示节拍〕不 Scan 脚本目录**
   `LayoutPages.cs` 的按钮是 `ScriptDriven = true; StartDemo(); LuaFlowHost.StartAll();`
   —— 没有 `Scan()`。`flows` 只在流程脚本页 / 自检里 Scan 过，用户没打开过流程脚本页时
   列表为空，`StartAll()` 启动 **0 条**，点下去同样「什么都没发生」。
   → `LuaFlowHost.StartAll()` 开头加 `if (flows.Count == 0) Scan();` 兜底。

3. **一轮结束 = Lua 线程结束**
   宿主 `running()` 绑的是 `f.Running && !stopAll`，`DoString` 一返回线程就结束、界面变
   「已退出」。原来 `start_line()` 没有 pcall 保护，任何一处抛错都会把整个脚本带走。
   → 主循环里 `pcall(start_line)`，出错只锁存这一轮（FAULT → 锁存停机 → 等复位），
   正常收尾就 `sleep(100)` 接着下一轮；只有 `running()` 变假才退出。

### 慢放为什么不破坏口径
- 轴：`SimMotionCard.Step` 的 dt 缩小 ⇒ 轴走慢；轴表 MaxVel/Acc、软限位、SR 判据一律不动，
  所以「轴速与真机一致」的自检（`cycle selftest` 读 `Cfg(ax).MaxVel`）不受影响。
- 脚本：`drive()` 只把 `pause(real)` 放大，`NOW += ms`、`RUN_MS += ms` 用原值 ⇒
  节拍分解、UPH、Index 全部还是真机口径。
- 两者用同一倍数，所以画布上「轴在走」和「脚本在等」是同步慢放，不会一个慢一个跳。

## 需求 75：画布轴速度 = 1 秒 10 像素

用户原话：「轴速度需要1秒10px、」（承接 74 那句没写完的「轴移动速度需要，，，」）

### 结论先行：不是改轴表，是改画布时间的算法

轴表 MaxVel 是**真机速度**（上料X 1500mm/s、横梁Y 800mm/s），一条轴 0.6s 走完全行程，
画布上就是「嗖一下」。用户要的是**画布上的位移速度**（px/s），所以不能动轴表，
只能把「时隙长度」从「按轴表时间反算」改成「按像素速度反算」。

### 实现（`ViewModels/LayoutPages.cs`）

```csharp
double pxSpeed = CanvasPxSpeed();                      // 读 点位.仿真.画布速度，默认 10
double SLOT_D = SlotByPx(Math.Max(UA_X1-UA_X0, BEAM_STROKE), pxSpeed);  // 398.79px ⇒ 113.9s
double SLOT_U = SlotByPx(Math.Max(U2_X1-U2_X0, BEAM_STROKE), pxSpeed);  // 398.79px ⇒ 113.9s
double SLOT_T = SlotByPx(armX1-armX0, pxSpeed);                          // 754px    ⇒ 215.4s
double CYC_SEC = SLOT_D + SLOT_U + SLOT_T;
```

`SlotByPx = 行程px ÷ (px速度 × 0.35)`，0.35 = `(1−PhaseHold)/2` —— 时隙里相位只在
前 35% 走完行程（两端各停 30%），和 `SlotSeconds()` 同一个系数。

三个时隙**不再等长**，所以槽定位从 `(int)(cyc/SLOT_SEC)` 改成按累计边界：
```csharp
double cyc = Mod(t, CYC_SEC);
int slot = cyc < SLOT_D ? 0 : (cyc < SLOT_D + SLOT_U ? 1 : 2);
double off = slot == 0 ? 0 : (slot == 1 ? SLOT_D : SLOT_D + SLOT_U);
double u = (cyc - off) / slotLen;
```
所有 `(3.0 * SLOT_SEC)`（8 处 demo 日志的循环号）一并换成 `(CYC_SEC)`。

### 口径（必须记住的一条）

各机构的画布比例差 7 倍（上料X 171.5px/900mm=0.19、下料X 290/900=0.32、
横梁 398.79/300=1.33、搬运 754/700=1.08 px/mm）。**物理上不可能让所有轴同时 10px/s**，
所以口径定为：**每个时隙里「行程最长的那根」= 设定值，其余按真机比例更慢**。
- 下料时隙：横梁 10.0px/s、下料X 7.3px/s
- 上料时隙：横梁 10.0px/s、上料X 4.3px/s
- 搬运时隙：搬运臂 10.0px/s

### 参数

`点位.仿真.画布速度`（px/s，MotionManager 构造时登记默认 10，界面的变量黑板可改）：

| 值 | 一轮（三个时隙） | 用途 |
|---|---|---|
| 10 | 443s（7.4 分钟） | 用户口径，动作慢到能逐个看清 |
| 30 | 148s | 看整段协同 |
| 100 | 44s | 快速过一遍 |
| 0 / 负数 | 8.2s | 退回需求 64 的真机时间口径 |

它只管「启动演示节拍」的画布演示；**脚本运行时的慢放仍是 `点位.仿真.慢放倍率`**，
两者互不覆盖（脚本每轮不再写这一项，避免把用户改的 0 盖回 10）。

## 需求 76：脚本为什么没跑起来 —— 中文在进 Lua 之前就被打成了 `?`

用户原话：「脚本没有跑起来？轴为什么一开始就在0位了」→「不要运行软件，后台自己测试啊」。
按这个要求，全程不启动 WPF，只用一个只加载 Lua 宿主的控制台探针（`%TEMP%\hg_lua_probe`）验证。

### 关键证据

```
[set] 原文=「h:3F3F2E3F3F」 解码=「??.??」      ← 中文进 Lua 前已是 0x3F
期望键 分选.启用 → 未命中   期望键 仿真.演示 → 未命中
进入开工：否    moveabs：0 条
self.__hx("中") = h:3F                          ← 连转义都只剩 '?'
```

`NLua.DoString(string)` 会把源码按系统 ANSI(GBK) 编码再交给 `luaL_loadbuffer`，
**源码里每个中文字符在进入 Lua 之前就已经变成 `?`（0x3F）**。于是
`boxget("仿真.演示")` 恒为 0 → 主循环永远落进待机分支 → 界面上就是
「刚开始就结束 / 轴一直停在原位」。上一轮加的 `\u{XXXX}` 转义不但没用，
还把 2 个 `?` 变成 6 个（转义结果是 UTF-8 字节，照样被打码）。

### 两处一起修

| # | 位置 | 改法 |
|---|---|---|
| ① | `Flow/LuaFlowHost.cs` `Run()` | `e.DoString(text)` → `e.State.LoadBuffer(Encoding.UTF8.GetBytes(text), name)` + `st.PCall(0,0,0)`，中文完整保留 |
| ② | 脚本顶层 `__wrapNames(...)` + C# `Unhex()` | 运行时字符串 interop 同样走 ANSI，所以所有 API 的名字参数编成 `h:`+UTF-8 十六进制（纯 ASCII）再过边界 |

`Unhex` 对没有 `h:` 前缀的字符串原样返回 ⇒ 01_上料XY 这类没装包装的旧脚本不受影响。

### 踩到的三个坑

1. **NLua 注册的委托在 Lua 里是 userdata，不是 function**（`type(f)=="function"` 会把包装全跳过）。
2. **转发参数必须保个数**：写成 `function(a,b,c,d)` 再 `f(a,b,c,d)` 会多传 nil，
   直接 `Cannot invoke delegate (invalid arguments for BoxSet)`；要用 `table.unpack(args,1,n)`。
3. **DLP 会把编辑器写的 `.lua` 透明加密**（头 `88 7D 1C`）：Lua 读到密文报
   `unexpected symbol near '?'`。只能 Python 写 `.tmp` + `os.replace`（`artifacts/_fix31*.py`），
   改完必须查 `head=45,45,32`（`-- `）确认明文。这条同样适用于以后所有 `.lua` 改动。
